# 05 · 应用场景

> 灵境能落到什么地方、每个场景里谁得到什么、以及它不该被用在哪。

**共同点**：每一种用法里，**收益方都是人类**，机器不产出结论。场景之间的差别只是"你要外化的是哪一类知识"。

---

## 一、个人经验萃取（最主推）

| 项 | 说明 |
|---|---|
| **对象** | 手艺 / 判断 / 决策类隐性经验持有者（工程师、医生、律师、老会计、匠人、管理者） |
| **怎么用** | 打开课室讲一段你最熟的东西 → 镜子（小明）按七类探测轮换追问 → 你回话 → 课后读"他问的 / 你答的"并排清单 |
| **得到什么** | 照出**自己没讲透的口子**。隐性知识（"我所知多于我能言说"）被逼成可描述的表达 |
| **为什么有效** | 定义式提问萃取不出隐性知识；案例 / 边界 / 权衡类提问可以。七类探测正是按这个设计的 |
| **落地形态** | 自托管，本机跑；经验内容不出设备 |

---

## 二、费曼式自测（用"教"来测自己）

| 项 | 说明 |
|---|---|
| **对象** | 正在学习的学生 / 转行者 / 备考者 / 自我校准的专业人 |
| **怎么用** | 把某个概念讲给 AI 学生听，看自己在哪一句开始含糊 |
| **得到什么** | 卡壳处的暴露。**不是分数**，是你自己读并排清单时心里那声"咯噔" |
| **与"对着空气讲"的区别** | 镜子会**真的追问**（引你原话、指向没讲透的位置），不是等你自言自语的空白 |
| **与"考自己"的区别** | 考试给分，这里只给你自己说过的话的原文并排；判定权不外移，所以不产生考试焦虑 |

---

## 三、团队培训 / 内部知识交接

| 项 | 说明 |
|---|---|
| **对象** | 需要把"老师傅脑子里的东西"留下来的团队；新员工入职训练；跨部门知识交接 |
| **怎么用** | 让熟悉业务的人讲一遍，把课后的「课堂纪要 + 讲授收获 + AI 理解笔记」当作交接材料归档 |
| **得到什么** | 一份**由讲者本人确认过**的结构化材料（双稿制：AI 镜稿 → 人五类修改 → 人定稿），而不是会议录音转写 |
| **为什么比"写文档"好推行** | 门槛是"讲一小时"，不是"写一份文档"；且讲者会主动修正 AI 理解偏的地方 |
| **注意** | 灵境不评估员工、不出考核分：**架构里根本没有"学生 → 分数"这条边**，拿它做绩效工具是误用 |

---

## 四、教学能力训练（教师 / 师范生 / 讲师）

| 项 | 说明 |
|---|---|
| **对象** | 新手教师、师范生、企业内训师、需要频繁做技术分享的人 |
| **怎么用** | 把要讲的课先讲给 AI 学生，接收七类探测，练"被追问时不慌、能把机制讲出来" |
| **得到什么** | 课前把"学生会问什么"先撞一遍；课后拿到自己回答的节奏曲线（第 k 轮你回了多少字） |
| **典型收获** | 学生用术语追问时才发现自己一直在"甩术语"；逻辑跳步的地方被"中间怎么发生的"钉出来 |

---

## 五、专家访谈 / 知识工程的前置步骤

| 项 | 说明 |
|---|---|
| **对象** | 要做专家系统的团队；做课程设计的教研组；做 SOP 提炼的运营团队 |
| **怎么用** | 访谈前先让专家跑一课，把"确定性薄弱点定位层"钉出的口子（用术语未解释 / 逻辑跳跃 / 突然从具体到抽象 / 照本宣科 / 该讲未讲）当作访谈提纲 |
| **得到什么** | 访谈提纲不再靠访谈者猜；提纲来自专家**自己讲的话**里的真实薄弱点 |
| **为什么这是灵境的强项** | 定位层是**确定性、可复现**的（见 [04](04-技术参考.md#二确定性薄弱点定位层p0-1)），同一段讲解跑两次得到同一组口子，可以进工作流、可以复核 |

---

## 六、学习科学 / 教育技术研究

| 项 | 说明 |
|---|---|
| **对象** | 教育技术研究者、认知科学研究组、想验证"可教代理"范式的团队 |
| **怎么用** | clone 下来自跑（零依赖，Node 22+），改造探测策略或定位层，观察"不评分、只提问"的架构如何落地 |
| **得到什么** | 一个**可跑、可复现、有测试守护**的对照物：不评分不是口号，是世界模型里没有那条边 |
| **可获得的数据** | 探测构成（七类计数）、薄弱点信号分布、跨课无知地图增长。**全是计数，不含任何"理解度"** |
| **诚实边界** | 研究引用是灵境的**设计依据**，不是"灵境已达到论文效果"的证据 |

---

## 七、不适用 / 误用清单

| 场景 | 为什么不适合 |
|---|---|
| **当成绩 / 考核工具** | 架构里没有"学生 → 分数"边；任何"AI 判断你答到了没有"的输出都是假的 |
| **当答疑机器人（问它要答案）** | 灵境的学生是"学徒"，它的价值在提问不在答问；要答案请用别的工具 |
| **当知识库 / 检索系统** | 它不索引、不检索、不回答事实问题 |
| **当孩子的看护 / 情感陪伴** | 主动不做出情感依赖诱导；界面显著标明"在与 AI 而非自然人交互" |
| **当公网多租户 SaaS（未做加固前）** | 当前无账号、无鉴权、单人本机定位；公网运营前须过合规清单，见 [06](06-许可与合规.md) |
| **拿"AI 学生悟了"做演示卖点** | 对外口径红线：不说"AI 学生学会了"（见 [01](01-产品作用.md) 第七节） |

## 八、部署形态对照

| 形态 | 谁适合 | 状态 |
|---|---|---|
| **本机自托管**（`node server.js`，浏览器打开） | 个人、研究者、内训师 | **已落**，推荐 |
| **内网服务器自托管**（团队共用一台） | 团队培训 / 教研组 | **已落**（同一份代码，自行加反向代理与访问控制） |
| **公网公共服务** | — | **未做**；须先补账号 / 鉴权 / 限流 / 合规备案 / TLS / 存储 TTL |
